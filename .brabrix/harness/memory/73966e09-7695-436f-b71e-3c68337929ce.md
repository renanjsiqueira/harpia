# harpia.yaml mantém capabilities/providers mesmo no MVP sem M2

O schema congelado do harpia.yaml inclui os blocos capabilities: e providers: (conforme prompt-initial.md §9/§14/§15/§16), não as chaves planas vendor/javaVersion sugeridas em design.md §9. No M1 apenas persistence:postgres é aceito; authentication/email/events com enabled:true são rejeitados com HRP4001/HRP4003 citando o escopo, sem geração parcial. Motivo: a separação Business/Capability/Provider é requisito arquitetural explícito, e o schema plano tornaria o YAML do M2 um breaking change.
